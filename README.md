# 국내 여행 추천 프로그램 (LLM + 지도 API 연동)

여행 날짜 하나만 입력하면, AI가 그 시기에 어울리는 국내 여행지를 추천하고
그 지역의 맛집을 찾은 뒤, 종합 여행 리포트(Markdown)를 자동으로 만들어주는
CLI(터미널 명령어) 프로그램입니다.

## 1. 프로젝트 소개

이 프로그램은 하나의 API 호출로 끝나지 않고, 서로 다른 두 API의 결과를
연결해서 하나의 결과물을 만들어내는 것이 핵심입니다.

**전체 흐름**

```
날짜 입력
   ↓
[1] LLM(Gemini)에게 "이 날짜에 어디로 여행가면 좋을지" 물어봄
   → 추천 도시, 날씨 요약, 행사 정보, 추천 이유를 JSON으로 받음
   ↓
[2] 추천받은 도시 이름으로 지도 API(Kakao Local)에서 맛집을 검색
   → 맛집 이름, 주소, 카테고리, 링크 등을 받음
   ↓
[3] 위 두 결과를 다시 LLM(Gemini)에게 넘겨서
    사람이 읽기 좋은 최종 여행 리포트(Markdown)를 생성
   ↓
results/ 폴더에 JSON(원본 데이터) + MD(리포트) 저장
```

즉 "LLM의 출력"을 "다음 API 호출의 입력"으로 다시 사용하는 것이
이 프로그램의 설계 포인트입니다.

## 2. 사용 기술 및 API

| 구분 | 선택 | 이유 |
|---|---|---|
| LLM API | Google Gemini (`gemini-3.6-flash`) | 무료로 시작하기 쉽고, JSON 형태로 결과를 뽑아내는 데 충분히 빠르고 정확함 |
| 지도/장소 API | Kakao Local (키워드 검색) | 국내 장소 검색에 특화되어 있고, REST API 키 하나로 간단히 인증 가능 |

**주요 파이썬 라이브러리**

| 라이브러리 | 역할 |
|---|---|
| `argparse` | 터미널에서 `--date` 옵션을 입력받고, 값이 없거나 형식이 틀리면 자동으로 에러 처리 |
| `google-genai` | Gemini API 호출 (1차 추천, 최종 리포트 생성 두 곳에서 사용) |
| `requests` | Kakao Local API에 HTTP 요청을 보내고 응답을 받음 |
| `python-dotenv` | `.env` 파일에 저장된 API 키를 코드로 안전하게 불러옴 |
| `json` | LLM 응답 문자열을 파이썬 딕셔너리로 변환하고, 결과를 파일로 저장 |
| `pathlib.Path` | `results/` 폴더 및 파일 경로를 운영체제에 상관없이 다룸 |

## 3. 설치 및 실행 방법

### 요구 사항
- Python 3.10 이상

### 설치
```bash
pip install -r requirements.txt
```

### API 키 설정
1. `.env.example` 파일을 복사해서 `.env` 파일을 만듭니다.
2. `.env` 파일을 열어 아래처럼 본인의 키 값을 채워 넣습니다. (실제 키 값은 저장소에 절대 올리지 않습니다)

```
GEMINI_API_KEY=여기에_본인의_Gemini_API_키
KAKAO_REST_API_KEY=여기에_본인의_Kakao_REST_API_키
```

- Gemini 키 발급: https://aistudio.google.com/apikey
- Kakao REST API 키 발급: https://developers.kakao.com → 내 애플리케이션 → 앱 키 → REST API 키

### 실행
```bash
python main.py --date "2026-03-15"
```

**실행 시 출력 예시**
```
[1/3] 1차 추천 생성 중(LLM)...
[2/3] 맛집 검색 중(지도/장소 API)...
[3/3] 최종 리포트 생성 중(LLM)...
완료! results/2026-03-15_travel_plan.md 를 확인하세요.
```

날짜 형식이 틀리면(`--date "2026/03/15"` 등) 사용법 안내와 함께 프로그램이 안전하게 종료됩니다.

## 4. 프로그램 동작 구조 (핵심 함수 설명)

### `get_recommendation(date, errors)` — 1차 여행지 추천
- 입력받은 날짜를 프롬프트에 넣어 Gemini에게 도시/날씨/행사/추천이유를
  **순수 JSON 형식으로만** 응답하도록 요청합니다.
- 응답이 JSON으로 파싱되지 않으면, "필수 키만 다시 JSON으로 출력하라"는
  프롬프트로 **딱 1회만 재요청**합니다. (무한 재시도 방지)
- 그래도 실패하면 `errors` 리스트에 실패 내용을 기록하고 `None`을 반환하여
  프로그램이 멈추지 않고 다음 단계로 넘어가도록 합니다.

### `search_restaurants(city, errors)` — 맛집 검색
- Kakao Local 키워드 검색 API(`"{도시} 맛집"`)를 호출해 최대 5곳을 가져옵니다.
- 아래 상황에서도 프로그램이 죽지 않고 빈 리스트(`[]`)를 반환하며,
  대신 `errors`에 원인을 기록합니다.
  - API 키 미설정
  - 인증 실패 (HTTP 401/403)
  - 네트워크 오류/타임아웃(10초)
  - 검색 결과 0건

### `generate_report(date, rec_json, restaurants, errors)` — 최종 리포트 생성
- 1차 추천 결과와 맛집 목록을 요약해서 Gemini에게 넘기고,
  정해진 7개 섹션 구조의 마크다운 리포트를 만들도록 요청합니다.
- 맛집이 없으면 "데이터 없음", 오류가 없으면 "없음"이라고 쓰도록
  프롬프트에 명시합니다.
- **Gemini 호출 자체가 실패해도** `_fallback_report()` 함수가 같은 구조의
  리포트를 파이썬 코드로 직접 조립해서 반환합니다. 즉 LLM이 응답을 못 줘도
  리포트 파일은 항상 만들어집니다.

### 캐싱 로직 — `load_cached_plan(date)` / `save_plan(...)`
- 프로그램 시작 시 `results/{date}_travel_plan.json`이 이미 있으면,
  그 안의 추천/맛집/오류 데이터를 그대로 불러와 **API 호출(1차 추천, 맛집 검색)을
  건너뜁니다.**
- 리포트 생성만 다시 실행해서 `.md` 파일을 새로 만듭니다.
- 캐시가 없으면 처음부터 전체 흐름(추천 → 검색 → 리포트)을 실행합니다.

## 5. 에러 처리 정책 요약

| 상황 | 처리 방식 |
|---|---|
| Gemini API 키(`GEMINI_API_KEY`) 미설정 | 즉시 종료하고, 발급 방법과 `.env` 설정법을 안내 |
| Kakao API 키 미설정 / 인증 실패(401·403) | 맛집 섹션을 "데이터 없음"으로 처리하고 프로그램은 계속 진행 |
| 맛집 검색 결과 0건 | 같은 방식으로 "데이터 없음" 처리 후 계속 진행 |
| 네트워크 오류·타임아웃(맛집 검색) | 오류를 기록하고 "데이터 없음"으로 처리 후 계속 진행 |
| 1차 추천 JSON 파싱 실패 | "필수 키만 다시 출력하라"는 프롬프트로 **1회만** 재시도, 그래도 실패하면 오류 기록 후 진행 |
| 최종 리포트 생성(LLM) 실패 | 오류를 기록하고, 파이썬으로 직접 조립한 대체(fallback) 리포트를 생성 |

모든 오류는 최종 JSON 파일의 `errors` 배열에 `{"step", "type", "message"}` 형태로
기록되며, 리포트의 "오류 요약" 섹션에도 반영됩니다.

## 6. 결과물 확인 방법

실행이 끝나면 `results/` 폴더에 아래 두 파일이 생성됩니다.

- `results/{date}_travel_plan.json`
  - `recommendation`: 1차 추천 결과(도시/날씨/행사/이유)
  - `restaurants`: 맛집 검색 결과 리스트 (0건일 수 있음)
  - `errors`: 실행 중 발생한 오류 목록 (없으면 빈 리스트)
- `results/{date}_travel_plan.md`
  - 추천 지역, 추천 이유, 날씨 요약, 행사/축제, 맛집 추천,
    1일 일정 제안(오전/오후/저녁), 오류 요약까지 담긴 최종 리포트

## 7. 보너스 과제 — 결과 캐싱

**왜 필요한가**: 같은 날짜로 여러 번 테스트하거나 리포트 문구만 다시 뽑고 싶을 때
매번 LLM/지도 API를 호출하면 시간과 비용(API 사용량)이 낭비됩니다.

**동작 방식**:
1. 프로그램 실행 시 가장 먼저 `results/{date}_travel_plan.json` 파일이
   있는지 확인합니다.
2. **있으면** → `[캐시 발견]` 메시지를 출력하고, 그 파일 안의 추천/맛집/오류
   데이터를 그대로 재사용합니다. 이때 1차 추천과 맛집 검색 API는 호출하지 않고,
   리포트 생성 단계만 다시 실행해 `.md` 파일을 새로 만듭니다.
3. **없으면** → 기존과 동일하게 처음부터(1차 추천 → 맛집 검색 → 리포트 생성)
   전체 흐름을 실행합니다.

## 8. API 키 보안 안내

- API 키는 코드나 README에 절대 직접 작성하지 않고, `.env` 파일에서
  `python-dotenv`로 읽어옵니다.
- `.env`는 `.gitignore`에 등록되어 있어 Git/GitHub에 올라가지 않습니다.
  (대신 값이 비어있는 `.env.example`을 제공해 설정 형식만 안내합니다)
- 이렇게 관리하면:
  - 실수로 키가 공개 저장소에 노출되는 사고를 막을 수 있고,
  - 키를 나중에 교체하더라도 코드를 수정할 필요가 없으며,
  - 사용량 제한이 있는 API에서 무단 사용으로 인한 과금 사고를 예방할 수 있습니다.
